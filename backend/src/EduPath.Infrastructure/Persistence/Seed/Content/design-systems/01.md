## Навіщо токени

Токен — це іменоване значення дизайн-рішення: колір, відступ, радіус, тінь. Замість `#116D63`
у сорока місцях макета і коду з'являється одна назва. Змінити колір бренду — означає змінити одне значення.

Проблема починається, коли токенів лише один рівень. Назва `teal-700` нічого не каже про призначення:
кнопка це, посилання чи фон бейджа? Коли знадобиться темна тема, доведеться переглядати кожен екран.

## Два рівні токенів

1. **Базові (primitive)**: `blue-600`, `gray-100`, `teal-700` — палітра без змісту. Вони описують,
   які кольори взагалі є в системі.
2. **Семантичні (semantic)**: `text-primary`, `surface-raised`, `border-danger` — посилаються на базові
   й описують роль.

```text
Базові                     Семантичні (світла)        Семантичні (темна)
teal-700  #116D63  ←──     action-primary              ──→ teal-400
gray-900  #15201E  ←──     text-primary                ──→ gray-50
gray-50   #F5F7F6  ←──     surface-page                ──→ gray-950
red-600   #C93A3A  ←──     border-danger               ──→ red-400
```

Компоненти використовують лише семантичні токени. Кнопка знає, що її фон — `action-primary`,
і не знає, що це бірюзовий. Тоді темна тема — це інший набір значень, а не перемальовані екрани:
семантичні токени перепризначаються на інші базові, а компоненти не змінюються.

## Як називати

Поширена схема — `категорія-роль-варіант-стан`:

- `text-primary`, `text-muted`, `text-on-action`
- `surface-page`, `surface-raised`, `surface-sunken`
- `border-default`, `border-strong`, `border-danger`
- `action-primary`, `action-primary-hover`

Уникайте назв за виглядом (`text-dark-gray`) — після зміни теми вони почнуть брехати.

## Відступи й інші токени

Ті самі принципи діють для решти властивостей:

- **Відступи**: базова шкала `space-1 … space-12` (4, 8, 12, 16, 24, 32…), семантичні — рідше потрібні,
  але корисні для повторюваних патернів: `card-padding`, `page-gutter`.
- **Радіуси**: `radius-sm` для полів, `radius-lg` для карток, `radius-pill` для бейджів.
- **Тіні**: два-три рівні піднесення, а не нова тінь для кожної картки.

## Токени у Figma

Figma Variables підтримують обидва рівні й режими (modes):

1. Колекція **Primitives** з палітрою.
2. Колекція **Semantic** з режимами Light і Dark, де кожна змінна посилається на примітив.
3. Компоненти використовують лише змінні з Semantic.

Перемикання режиму на фреймі показує макет у темній темі без жодного дублювання.

## Токени в коді

```css
:root {
  --teal-700: #116d63;
  --action-primary: var(--teal-700);
}

[data-theme='dark'] {
  --action-primary: var(--teal-400);
}

.button-primary { background: var(--action-primary); }
```

Для синхронізації з Figma використовують експорт змінних у JSON і генерацію CSS або TypeScript з нього,
щоб значення не копіювалися вручну.

## Практика

Випишіть усі кольори, що трапляються у вашому продукті. Згрупуйте їх у базову палітру, визначте 10–15
семантичних ролей і перепишіть один компонент так, щоб він використовував лише семантичні токени.
Перевірте, чи можна отримати темну версію, змінивши тільки значення токенів.
