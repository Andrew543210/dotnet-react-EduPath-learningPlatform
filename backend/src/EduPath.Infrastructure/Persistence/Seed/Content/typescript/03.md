## Навіщо generics

Функція, що бере перший елемент масиву, з типом `any[]` повертає `any` — і типізація закінчується:

```ts
function first(items: any[]) {
  return items[0]
}
const course = first(courses) // any: помилки в course.titel ніхто не помітить
```

Generic зберігає зв'язок між типом входу й виходу:

```ts
function first<T>(items: T[]): T | undefined {
  return items[0]
}
const course = first(courses) // Course | undefined
```

Параметр `T` визначається під час виклику. Явно писати `first<Course>(courses)` не потрібно —
TypeScript виводить тип з аргументу.

## Узагальнена функція зберігає зв'язок типів

```ts
function groupBy<T, K extends string>(items: T[], key: (item: T) => K) {
  const result = {} as Record<K, T[]>
  for (const item of items) (result[key(item)] ??= []).push(item)
  return result
}

const byLevel = groupBy(courses, (c) => c.level)
// Record<'Beginner' | 'Intermediate' | 'Advanced', Course[]>
```

Тип ключів виводиться з функції `key`: якщо `level` — об'єднання трьох літералів, результат матиме
рівно ці ключі. Звернення до `byLevel.Expert` дасть помилку компіляції.

## Обмеження extends

Обмеження описує, що generic має вміти:

```ts
function byId<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id)
}
```

Функція працює з курсами, уроками, користувачами — з усім, що має `id`, і повертає той самий конкретний тип.

`keyof` разом з generic дає типобезпечний доступ до властивостей:

```ts
function sortBy<T, K extends keyof T>(items: T[], key: K): T[] {
  return [...items].sort((a, b) => (a[key] < b[key] ? -1 : a[key] > b[key] ? 1 : 0))
}

sortBy(courses, 'price')   // добре
sortBy(courses, 'prise')   // помилка: такої властивості немає
```

## Generics у React

```tsx
type SelectProps<T> = {
  options: T[]
  value: T
  getLabel: (option: T) => string
  onChange: (option: T) => void
}

function Select<T>({ options, value, getLabel, onChange }: SelectProps<T>) {
  /* ... */
}

<Select options={levels} value={level} getLabel={(l) => t.levels[l]} onChange={setLevel} />
```

Тип `T` виводиться з `options`, і `onChange` отримує саме `CourseLevel`, а не `string`.

Інший приклад — типізований хук запиту: `useQuery<CourseDetails>` повертає `data` з правильним типом
у кожному компоненті.

## Коли generic не потрібен

- Якщо `T` використовується лише один раз — у параметрі, — достатньо конкретного типу або `unknown`.
- Не додавайте параметри «на майбутнє»: generic з п'ятьма параметрами важче читати, ніж два окремі типи.
- Не пишіть `<T = any>` — це повертає `any` через чорний хід.

## Практика

Знайдіть у проєкті дві-три функції-утиліти, які приймають або повертають `any` (пошук, групування, сортування).
Перепишіть їх на generics з обмеженнями й перевірте, що місця виклику не потребують жодних змін.
