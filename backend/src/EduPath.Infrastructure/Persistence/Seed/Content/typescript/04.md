## Типи з інших типів

Коли та сама сутність потрібна в кількох формах — повна модель, форма створення, форма редагування,
картка в списку, — найгірше рішення — описувати кожну форму вручну. Поля розходяться, і через місяць
`CourseCard` має `price`, а `Course` — уже `priceUah`. TypeScript дозволяє виводити одні типи з інших.

## Вбудовані utility types

```ts
type Course = {
  id: number
  title: string
  summary: string
  price: number
  status: 'Draft' | 'Published'
  publishedAt: string | null
}
```

**Partial<T>** — усі поля необов'язкові. Підходить для патчу або форми редагування, де змінюють частину полів:

```ts
function updateCourse(id: number, patch: Partial<Course>) { /* ... */ }
updateCourse(5, { price: 490 })
```

**Required<T>** — навпаки, робить усі поля обов'язковими.

**Pick<T, K>** і **Omit<T, K>** — DTO з частини полів:

```ts
type CourseCard = Pick<Course, 'id' | 'title' | 'price'>
type CourseDraft = Omit<Course, 'id' | 'publishedAt'>
```

**Record<K, V>** — словник із відомими ключами:

```ts
const statusLabel: Record<Course['status'], string> = {
  Draft: 'Чернетка',
  Published: 'Опубліковано',
}
```

Якщо додати новий статус, TypeScript вимагатиме додати й підпис.

**ReturnType**, **Parameters**, **Awaited** — типи з функцій:

```ts
type CatalogResponse = Awaited<ReturnType<typeof fetchCatalog>>
```

## Mapped types

Усі utility types вище — це mapped types, які можна писати й самостійно. Синтаксис нагадує цикл по ключах:

```ts
type Nullable<T> = { [K in keyof T]: T[K] | null }

type FormErrors<T> = { [K in keyof T]?: string }

const errors: FormErrors<CourseDraft> = { title: 'Назва занадто коротка' }
```

Модифікатори `readonly` і `?` можна додавати або прибирати через `+` і `-`:

```ts
type Mutable<T> = { -readonly [K in keyof T]: T[K] }
```

Перейменування ключів через `as` дозволяє генерувати, наприклад, назви обробників:

```ts
type Handlers<T> = { [K in keyof T as `on${Capitalize<string & K>}Change`]: (value: T[K]) => void }
// { onTitleChange: (value: string) => void; onPriceChange: (value: number) => void; ... }
```

## Індексний доступ

`Course['status']` дає тип поля, `Course[keyof Course]` — об'єднання типів усіх полів.
Для масивів: `typeof levels[number]` перетворює `const levels = ['Beginner', 'Advanced'] as const`
на `'Beginner' | 'Advanced'`. Так один масив слугує і даними для селекту, і типом.

## Міра

Mapped types — потужний інструмент, але тип на п'ять рядків з умовними типами всередині колеги будуть
розбирати довше, ніж ви його писали. Якщо похідний тип не вміщується в рядок-два, дайте йому назву
і поясніть призначення назвою, а не коментарем.

## Практика

Візьміть модель зі свого проєкту й виведіть з неї тип форми створення (`Omit`), форми редагування (`Partial`),
картки списку (`Pick`) і помилок валідації (mapped type). Видаліть вручну написані дублікати.
