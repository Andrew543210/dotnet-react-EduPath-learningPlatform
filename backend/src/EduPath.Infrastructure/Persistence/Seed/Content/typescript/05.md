## Типи зникають під час виконання

TypeScript перевіряє код під час компіляції, а потім стирає всі типи — у браузер потрапляє звичайний JavaScript.
Типи TypeScript не існують після компіляції, тож рядок

```ts
const course = (await res.json()) as Course
```

нічого не перевіряє. Якщо бекенд перейменував поле або повернув `null` замість масиву,
помилка з'явиться не тут, а десь у глибині компонента: `Cannot read properties of undefined`.

Дані ззовні — відповіді API, `localStorage`, параметри URL, повідомлення WebSocket — треба перевіряти під час виконання.

## Схема zod: перевірка і тип з одного джерела

```ts
import { z } from 'zod'

const CourseSchema = z.object({
  id: z.number().int(),
  title: z.string().min(1),
  price: z.number().nonnegative(),
  level: z.enum(['Beginner', 'Intermediate', 'Advanced']),
  publishedAt: z.string().datetime().nullable(),
})

type Course = z.infer<typeof CourseSchema>
```

`z.infer<typeof Schema>` повертає тип TypeScript, описаний схемою. Схема і тип не можуть розійтися:
змінили схему — змінився тип.

```ts
async function getCourse(id: number): Promise<Course> {
  const res = await fetch(`/api/courses/${id}`)
  return CourseSchema.parse(await res.json())
}
```

`parse` повертає дані з правильним типом або викидає `ZodError` з описом кожного невідповідного поля.
Якщо виняток не потрібен, використовуйте `safeParse`:

```ts
const result = CourseSchema.safeParse(json)
if (!result.success) {
  logger.warn(result.error.issues)
  return null
}
return result.data
```

## Перетворення під час перевірки

Схема може не лише перевіряти, а й нормалізувати дані:

```ts
const QuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  search: z.string().trim().optional(),
})

const query = QuerySchema.parse(Object.fromEntries(new URLSearchParams(location.search)))
```

`coerce` перетворює рядок з URL на число, `default` підставляє значення за замовчуванням.

## Одна схема — і для форми, і для відповіді API

З react-hook-form схема підключається через резолвер, і правила валідації форми збігаються з типом даних:

```ts
const form = useForm<CourseDraft>({ resolver: zodResolver(CourseDraftSchema) })
```

Похідні схеми будуються як похідні типи з попереднього уроку: `CourseSchema.pick({ title: true })`,
`.partial()`, `.extend({ ... })`.

## Де перевіряти

- На **межі** застосунку: в API-клієнті, при читанні зі сховища, при розборі URL.
- Не всередині компонентів — далі по коду дані вже мають правильний тип.
- Не дублюйте перевірки сервера в кожній точці: схема фронтенду захищає від неочікуваної форми даних,
  а бізнес-правила залишаються на бекенді.

## Підсумок курсу

Звуження й дискриміновані об'єднання роблять неможливі стани невиразними, generics і utility types
зберігають зв'язки між типами без дублювання, а схеми закривають останню діру — дані, що приходять ззовні.

## Практика

Додайте схеми zod для двох-трьох найважливіших відповідей API свого проєкту й підключіть `parse`
в API-клієнті. Змініть назву поля на бекенді й переконайтеся, що помилка тепер видна одразу й зрозуміло.
