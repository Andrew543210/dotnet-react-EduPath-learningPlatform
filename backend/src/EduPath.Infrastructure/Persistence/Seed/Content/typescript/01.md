## Компілятор стежить за перевірками

TypeScript аналізує потік керування: після кожної перевірки він знає, яким може бути значення
в цій гілці коду. Це називається **звуженням типу** (narrowing).

```ts
function title(course: Course | null) {
  if (!course) return 'Курс не знайдено'
  return course.title // тут course: Course
}
```

Після `return` у першій гілці `null` уже неможливий, тож звертання до `course.title` безпечне.
Жодних приведень типів не потрібно.

## Інструменти звуження

**typeof** — для примітивів:

```ts
function formatPrice(value: number | string) {
  if (typeof value === 'number') return value.toFixed(2)
  return value.trim()
}
```

**in** — перевіряє наявність властивості:

```ts
type Video = { url: string; durationSec: number }
type Article = { markdown: string }

function preview(lesson: Video | Article) {
  return 'url' in lesson ? `Відео, ${lesson.durationSec} с` : lesson.markdown.slice(0, 120)
}
```

**instanceof** — для класів, наприклад помилок:

```ts
try {
  await api.post('/payments', payload)
} catch (error) {
  if (error instanceof ApiError && error.status === 422) showFieldErrors(error.fieldErrors)
  else throw error
}
```

**Рівність** — порівняння з літералом звужує об'єднання літералів: після `if (role === 'Admin')` змінна має тип `'Admin'`.

## Власні type guard

Коли перевірка складна, її виносять у функцію з предикатом `value is Type`:

```ts
function isPublished(course: Course): course is PublishedCourse {
  return course.status === 'Published' && course.publishedAt !== null
}

const visible = courses.filter(isPublished) // PublishedCourse[]
```

Функція-предикат — це обіцянка компілятору. Якщо перевірка всередині неправильна, TypeScript повірить
і помилка вилізе під час виконання. Покривайте такі функції тестами.

## Чому `as` — запах

```ts
const course = data as Course
```

`as` не перевіряє нічого — він вимикає перевірку. Якщо доводиться писати `as`, найчастіше тип описано
неточно: функція повертає `any`, об'єднання неповне або дані прийшли ззовні без валідації.
Замість приведення:

- уточніть тип джерела (типізуйте відповідь API, параметр функції);
- додайте перевірку, яка звузить тип;
- для зовнішніх даних використовуйте валідацію схемою — про це останній урок курсу.

Виправданий `as` трапляється рідко: наприклад, `as const` для літералів або робота з DOM,
коли ви точно знаєте тип елемента.

## Увімкніть strict

Звуження працює повноцінно лише з `"strict": true` у `tsconfig.json`. Без `strictNullChecks`
тип `Course` мовчки включає `null`, і перевірки на `null` нічого не дають компілятору.

## Практика

Знайдіть у своєму проєкті три місця з `as` або `!` (non-null assertion). Для кожного спробуйте
переписати код так, щоб тип звужувався перевіркою, і перевірте, чи не знайшовся при цьому прихований баг.
