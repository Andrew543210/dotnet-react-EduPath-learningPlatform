## Застосунок і база однією командою

Новий розробник у команді має запустити проєкт локально. Без Docker це означає встановити PostgreSQL
потрібної версії, створити базу й користувача, налаштувати рядок підключення. З docker compose —
одна команда: `docker compose up`.

## docker-compose.yml

```yaml
services:
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_DB: shop
      POSTGRES_USER: shop
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-shop}
    volumes:
      - db-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U shop -d shop"]
      interval: 5s
      timeout: 3s
      retries: 20

  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
    environment:
      ConnectionStrings__Default: Host=db;Port=5432;Database=shop;Username=shop;Password=${POSTGRES_PASSWORD:-shop}
      ASPNETCORE_ENVIRONMENT: Development
    ports:
      - "8080:8080"

volumes:
  db-data:
```

## Мережа між сервісами

Compose створює спільну мережу, у якій сервіси бачать одне одного за іменами. Тому в рядку підключення
вказано `Host=db`, а не `localhost`: усередині контейнера `api` адреса `localhost` — це сам контейнер `api`.

Порт бази назовні не публікується — до неї має доступ лише API. Якщо потрібно підключитися з IDE,
додайте `ports: ["5432:5432"]` лише в локальний override-файл.

## healthcheck і depends_on

`depends_on` без умови лише гарантує, що контейнер бази **запущено**, але PostgreSQL ще кілька секунд
ініціалізується. API стартує, пробує застосувати міграції й падає.

`healthcheck` з `pg_isready` перевіряє, що база справді приймає підключення, а `condition: service_healthy`
змушує API чекати саме на цей стан.

## Конфігурація через змінні середовища

ASP.NET Core читає змінні середовища поверх `appsettings.json`. Подвійне підкреслення відповідає вкладеності:
`ConnectionStrings__Default` перевизначає `ConnectionStrings:Default`, `Jwt__SigningKey` — `Jwt:SigningKey`.

Секрети не записують у `docker-compose.yml`. Синтаксис `${POSTGRES_PASSWORD:-shop}` бере значення з файлу `.env`
поруч із compose-файлом або підставляє значення за замовчуванням для локальної розробки. Файл `.env` додають
у `.gitignore`, а в репозиторії тримають `.env.example` з описом змінних.

## Дані між перезапусками

Іменований том `db-data` зберігає файли бази окремо від контейнера. `docker compose down` зупиняє і видаляє
контейнери, але дані залишаються. Щоб почати з чистої бази — `docker compose down -v`.

## Корисні команди

```bash
docker compose up --build -d    # зібрати й запустити у фоні
docker compose logs -f api      # логи API
docker compose exec db psql -U shop -d shop
docker compose down             # зупинити, дані залишаються
```
