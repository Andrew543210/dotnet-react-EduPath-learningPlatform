## Чому образ не має містити SDK

Найпростіший Dockerfile для ASP.NET Core бере образ із SDK, копіює код і запускає `dotnet run`. Він працює,
але образ важить близько 900 МБ, містить компілятор, кеш NuGet і вихідний код, а запуск щоразу триває довше,
бо проєкт збирається при старті контейнера.

Багатоетапна збірка розділяє роботу: етап `sdk` збирає застосунок, етап `aspnet` містить лише результат
публікації й середовище виконання. Образ стає в кілька разів меншим — близько 220 МБ, — і в ньому немає
нічого зайвого для атаки.

## Dockerfile

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src

COPY Directory.Build.props Directory.Packages.props ./
COPY src/Shop.Domain/Shop.Domain.csproj src/Shop.Domain/
COPY src/Shop.Api/Shop.Api.csproj src/Shop.Api/
RUN dotnet restore src/Shop.Api/Shop.Api.csproj

COPY src/ src/
RUN dotnet publish src/Shop.Api/Shop.Api.csproj -c Release -o /app --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY --from=build /app ./
USER app
ENV ASPNETCORE_URLS=http://+:8080
EXPOSE 8080
ENTRYPOINT ["dotnet", "Shop.Api.dll"]
```

## Кеш шарів: спершу залежності

Кожна інструкція створює шар, і Docker перевикористовує шар, якщо його вхідні дані не змінилися.
Порядок інструкцій вирішує, наскільки швидкими будуть повторні збірки:

1. Копіюємо **лише** `.csproj` і файли з версіями пакетів.
2. Виконуємо `dotnet restore` — цей шар залишається в кеші, поки не зміняться залежності.
3. Тільки потім копіюємо весь код і публікуємо.

Якщо скопіювати весь код до `restore`, будь-яка зміна в одному файлі змусить заново завантажувати всі пакети.

## .dockerignore

Без нього в контекст збірки потрапляють `bin`, `obj`, локальні бази й секрети:

```text
**/bin
**/obj
**/App_Data
tests
.vs
```

Менший контекст — швидша збірка і жодних випадкових файлів в образі.

## Безпека образу

- **Непривілейований користувач.** Образи `aspnet` з .NET 8 мають користувача `app`; інструкція `USER app`
  запускає процес без прав root.
- **Порт 8080**, а не 80: порти нижче 1024 вимагають прав root.
- **Конкретний тег** (`aspnet:10.0`), а не `latest`, — щоб збірка не змінилася несподівано.
- **Жодних секретів** в образі — лише змінні середовища під час запуску.

## Перевірка

```bash
docker build -t shop-api .
docker images shop-api
docker run --rm -p 8080:8080 shop-api
```

Порівняйте розмір образу з однокроковим варіантом і перевірте, що застосунок відповідає на `http://localhost:8080/health`.
