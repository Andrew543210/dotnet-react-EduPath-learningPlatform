## Три зони Git

Щоб упевнено відкочувати зміни, треба розуміти, де вони живуть:

1. **Робочий каталог** — файли на диску, як ви їх бачите в редакторі.
2. **Індекс (staging)** — те, що потрапить у наступний коміт після `git add`.
3. **Історія** — коміти.

Кожна команда відкату працює з певною зоною.

## Скасувати зміни у файлі

```bash
git restore src/Catalog.tsx            # повернути файл до стану останнього коміту
git restore --staged src/Catalog.tsx   # прибрати з індексу, зміни залишаться на диску
git restore --source=HEAD~3 src/Catalog.tsx   # взяти версію файлу з трьох комітів тому
```

Обережно: `git restore` без `--staged` безповоротно знищує незакомічені зміни у файлі.

## Скасувати опублікований коміт

Коміт уже в `main`, і колеги його забрали. Переписувати історію не можна — потрібен новий коміт,
який робить протилежне:

```bash
git revert 4c81a22
```

`revert` створює новий коміт, що скасовує зміни старого, — безпечно для спільних гілок. В історії
залишаються обидва: і помилка, і її скасування, з поясненням у повідомленні. Скасувати можна і злиття:
`git revert -m 1 <хеш-злиття>` прибере всі зміни, що прийшли з гілки.

## Прибрати локальні коміти

`git reset` пересуває вказівник гілки назад. Три режими відрізняються тим, що стається зі змінами:

| Команда | Коміти | Індекс | Робочий каталог |
|---|---|---|---|
| `git reset --soft HEAD~1` | прибрано | зміни залишаються підготовленими | без змін |
| `git reset HEAD~1` (`--mixed`) | прибрано | очищено | зміни залишаються у файлах |
| `git reset --hard HEAD~1` | прибрано | очищено | **зміни знищено** |

Найчастіший сценарій — «закомітив не те»: `git reset --soft HEAD~1` прибирає останній коміт,
залишаючи зміни підготовленими, тож можна виправити й закомітити знову. Для останнього коміту є ще
простіший варіант — `git commit --amend`.

`reset` переписує історію, тож використовуйте його лише для локальної роботи, яку ще ніхто не забрав.

## Відкласти зміни

```bash
git stash push -m "форма оплати, недороблено"
git switch main          # терміново виправити баг
git switch -
git stash pop
```

`stash` зберігає незакомічені зміни і повертає робочий каталог до останнього коміту.

## Якщо все зламалося

`git reflog` пам'ятає кожне положення `HEAD`, навіть після `reset --hard` і невдалого rebase:

```bash
git reflog
git reset --hard HEAD@{3}
```

Втрачено можна лише те, що ніколи не було закомічено або додано в stash.

## Шпаргалка

| Ситуація | Команда |
|---|---|
| Скасувати зміни у файлі | `git restore <файл>` |
| Прибрати файл з індексу | `git restore --staged <файл>` |
| Виправити останній коміт | `git commit --amend` |
| Скасувати опублікований коміт | `git revert <хеш>` |
| Прибрати локальні коміти, зберігши зміни | `git reset --soft HEAD~1` |
| Повернути стан після помилки | `git reflog` + `git reset --hard` |

## Практика

У тестовому репозиторії зробіть три коміти й відпрацюйте кожен рядок шпаргалки. Особливо — відновлення
після `git reset --hard` через `reflog`: після цього втратити роботу в Git буде значно складніше.
