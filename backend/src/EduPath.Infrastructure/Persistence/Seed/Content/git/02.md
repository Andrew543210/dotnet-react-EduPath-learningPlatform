## Гілка — це лише вказівник

У Git гілка — це файл з одним рядком: хешем коміту, на який вона вказує. Тому створити гілку
можна миттєво, а сотня гілок не займає місця. `HEAD` вказує на поточну гілку, і кожен новий коміт
пересуває її вперед.

```bash
git switch -c feature/certificates   # створити гілку й перейти на неї
git commit -m "Додати сторінку сертифіката"
git switch main                      # повернутися на main
git merge feature/certificates       # влити зміни
```

## Два види злиття

**Fast-forward.** Якщо в `main` після відгалуження не з'явилося нових комітів, Git просто пересуває
вказівник `main` на останній коміт гілки. Нового коміту не створюється, історія лінійна.

**Справжнє злиття.** Якщо обидві гілки пішли вперед, Git створює *коміт злиття* з двома батьками.
Він об'єднує зміни обох гілок.

```text
*   9d2f1aa Merge branch 'feature/certificates'
|\
| * 51c0e3b Додати QR-код на сертифікат
| * 8a7b204 Додати сторінку сертифіката
* | 2e44d19 Виправити сортування каталогу
|/
* 0f13c55 Додати каталог курсів
```

`git merge --no-ff` створює коміт злиття навіть там, де можливий fast-forward — так в історії
видно, які коміти прийшли разом з однією функцією.

## Конфлікти

Конфлікт виникає, коли обидві гілки змінили ті самі рядки. Git зупиняє злиття і позначає спірні місця:

```text
<<<<<<< HEAD
const pageSize = 12
=======
const pageSize = 20
>>>>>>> feature/catalog-grid
```

Що робити:

1. `git status` покаже файли з конфліктами.
2. Відкрийте файл, вирішіть, який варіант правильний (або поєднайте обидва), і приберіть маркери
   `<<<<<<<`, `=======`, `>>>>>>>`.
3. Запустіть збірку й тести — конфлікт міг бути не лише текстовим, а й логічним.
4. `git add <файл>` позначає конфлікт вирішеним.
5. `git commit` (або `git merge --continue`) завершує злиття.

Передумали зливати? `git merge --abort` поверне все, як було до початку.

## Як зменшити кількість конфліктів

- **Короткі гілки.** Гілка, що живе два дні, конфліктує рідше, ніж та, що живе два тижні.
- **Регулярно підтягуйте `main`** у свою гілку, щоб розв'язувати конфлікти малими порціями.
- **Не змішуйте форматування з логікою.** Переформатований файл конфліктує з усіма, хто його чіпав.
- **Домовтеся про назви гілок:** `feature/…`, `fix/…`, `chore/…` — так зрозуміло, що в гілці, без відкриття.

## Практика

Створіть дві гілки від `main`, змініть в обох один і той самий рядок і злийте їх по черзі.
Розв'яжіть конфлікт, переконайтеся, що застосунок збирається, і подивіться результат через
`git log --graph --oneline`.
