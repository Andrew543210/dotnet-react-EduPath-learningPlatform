## Не чекайте по черзі те, що можна чекати разом

Сторінка особистого кабінету показує профіль, замовлення й бонуси. Кожен запит до зовнішнього сервісу триває близько 300 мс.

```csharp
// Послідовно: 300 + 300 + 300 мс
var profile = await api.GetProfileAsync(id, ct);
var orders  = await api.GetOrdersAsync(id, ct);
var bonus   = await api.GetBonusAsync(id, ct);
```

Запити не залежать один від одного, тож їх можна запустити одночасно і дочекатися всіх разом:

```csharp
// Разом: близько 300 мс
var profileTask = api.GetProfileAsync(id, ct);
var ordersTask  = api.GetOrdersAsync(id, ct);
var bonusTask   = api.GetBonusAsync(id, ct);
await Task.WhenAll(profileTask, ordersTask, bonusTask);

return new Dashboard(profileTask.Result, ordersTask.Result, bonusTask.Result);
```

Виклик методу запускає операцію одразу — `await` лише чекає на результат. Після `Task.WhenAll` усі задачі
гарантовано завершені, тож `.Result` тут безпечний і не блокує потік.

## Винятки у WhenAll

Якщо впали дві задачі з трьох, `await Task.WhenAll(...)` викине **перший** виняток. Решту можна дістати
з властивості `Exception` повернутої задачі:

```csharp
var all = Task.WhenAll(tasks);
try { await all; }
catch
{
    foreach (var error in all.Exception!.InnerExceptions)
        logger.LogError(error, "Запит не вдався");
    throw;
}
```

`Task.WhenAny` повертає першу завершену задачу — зручно для тайм-аутів чи запиту до кількох дзеркал.

## Обмеження паралельності

Тисяча одночасних запитів до чужого API — це вже DoS-атака. Ви отримаєте `429 Too Many Requests`,
вичерпаєте сокети або покладете сервіс партнера. Для великих наборів даних обмежуйте кількість одночасних операцій.

**Parallel.ForEachAsync** (.NET 6+) — найпростіший варіант:

```csharp
await Parallel.ForEachAsync(userIds,
    new ParallelOptions { MaxDegreeOfParallelism = 8, CancellationToken = ct },
    async (id, token) => await SyncUserAsync(id, token));
```

**SemaphoreSlim** — коли потрібен тонший контроль, наприклад спільний ліміт для кількох місць у коді:

```csharp
private readonly SemaphoreSlim gate = new(8);

public async Task<string> FetchAsync(string url, CancellationToken ct)
{
    await gate.WaitAsync(ct);
    try { return await http.GetStringAsync(url, ct); }
    finally { gate.Release(); }
}
```

## DbContext і паралельні запити

`DbContext` в EF Core **не потокобезпечний**: два запити через один контекст одночасно запускати не можна.
EF Core перевіряє це і викидає `InvalidOperationException: A second operation was started on this context`.

```csharp
// Помилка: обидва запити йдуть через один db
await Task.WhenAll(db.Orders.ToListAsync(ct), db.Users.ToListAsync(ct));
```

Якщо паралельне читання з бази справді потрібне, створюйте окремі контексти через `IDbContextFactory<T>`.
Але спершу подумайте: часто один запит із `Include` або проєкцією швидший за два паралельні.

## Практика

Знайдіть у своєму коді місце з кількома незалежними `await` поспіль і перепишіть його через `Task.WhenAll`.
Виміряйте час до і після за допомогою `Stopwatch` або логів запитів.
