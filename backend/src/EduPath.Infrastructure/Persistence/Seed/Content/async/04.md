## Користувач закрив вкладку — сервер має зупинитися

Користувач відкрив звіт, який будується 20 секунд, і через три секунди закрив вкладку. Без скасування сервер
дорахує звіт до кінця, витратить з'єднання з базою і процесорний час, а результат нікому не потрібен.

ASP.NET Core знає, що клієнт від'єднався, і сигналізує про це токеном `HttpContext.RequestAborted`.
Якщо додати до дії контролера параметр типу `CancellationToken`, фреймворк підставить саме цей токен:

```csharp
[HttpGet("report")]
public Task<ReportDto> Report([FromQuery] int year, CancellationToken ct) =>
    reports.BuildAsync(year, ct);
```

## Прокидайте токен до самого низу

Токен корисний лише тоді, коли доходить до операцій, які вміють скасовуватися: EF Core, `HttpClient`, `Task.Delay`, канали.

```csharp
public async Task<ReportDto> BuildAsync(int year, CancellationToken ct)
{
    var orders = await db.Orders
        .Where(o => o.CreatedAt.Year == year)
        .ToListAsync(ct);

    var rates = await http.GetFromJsonAsync<Rates>("/rates", ct);

    foreach (var batch in orders.Chunk(1000))
    {
        ct.ThrowIfCancellationRequested();
        Aggregate(batch, rates);
    }
    return Result();
}
```

Для обчислень, які самі не перевіряють токен, викликайте `ct.ThrowIfCancellationRequested()` між ітераціями.

## OperationCanceledException — не помилка

Скасована операція завершується винятком `OperationCanceledException` (або його нащадком `TaskCanceledException`).
Не ковтайте його і не логуйте як помилку — дайте йому піднятися: це нормальний спосіб завершення.
ASP.NET Core сам розпізнає скасування через `RequestAborted` і не пише в лог помилку 500.

```csharp
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    throw;   // скасував клієнт — нічого не робимо
}
```

Фільтр `when` відрізняє скасування клієнтом від тайм-ауту, що стався всередині.

## Тайм-аути поверх токена запиту

Часто потрібно і поважати від'єднання клієнта, і не чекати зовнішній сервіс довше за п'ять секунд.
Для цього створюють зв'язане джерело через `CancellationTokenSource.CreateLinkedTokenSource`:

```csharp
using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
cts.CancelAfter(TimeSpan.FromSeconds(5));

var rates = await http.GetFromJsonAsync<Rates>("/rates", cts.Token);
```

Новий токен скасується, якщо скасовано вихідний `ct` **або** минуло п'ять секунд. `using` обов'язковий:
джерело тримає таймер і реєстрацію на батьківському токені.

## Правила

1. Приймайте `CancellationToken` останнім параметром кожного публічного асинхронного методу.
2. Передавайте його в кожен асинхронний виклик всередині — інакше скасування губиться на півдорозі.
3. Не ковтайте `OperationCanceledException`.
4. Не підставляйте `CancellationToken.None` «щоб скомпілювалося».
5. Не скасовуйте операції, які мають завершитися атомарно, наприклад запис платежу після списання коштів.

## Практика

До уроку додано шпаргалку `cancellation-cheatsheet.md`. Візьміть один довгий ендпоінт свого проєкту
і простежте, чи доходить токен до кожного звернення до бази та HTTP. Перевірте результат,
закривши вкладку посеред запиту: у логах бази запит має перерватися.
