## Метрика — це агрегат з групуванням

Майже кожна бізнес-метрика зводиться до однієї схеми: взяти рядки, розкласти їх на групи
і порахувати щось для кожної групи. Виручка за тиждень, середній чек за містом, конверсія за каналом.

```sql
SELECT date_trunc('week', created_at) AS week,
       COUNT(*)                AS orders,
       COUNT(DISTINCT user_id) AS buyers,
       SUM(total)              AS revenue,
       ROUND(AVG(total), 2)    AS avg_check
FROM orders
WHERE status = 'paid'
GROUP BY 1
ORDER BY 1;
```

`GROUP BY 1` посилається на перший стовпець `SELECT`. Це зручно в аналітиці, але в коді застосунку
краще писати вираз явно.

## Агрегатні функції

| Функція | Що рахує | Нюанс |
|---|---|---|
| `COUNT(*)` | кількість рядків | рахує і рядки з `NULL` |
| `COUNT(column)` | кількість не-`NULL` значень | |
| `COUNT(DISTINCT column)` | кількість унікальних значень | важка на великих таблицях |
| `SUM`, `AVG` | сума, середнє | ігнорують `NULL` |
| `MIN`, `MAX` | мінімум, максимум | працюють і з датами, і з рядками |

`AVG` ігнорує `NULL`, тож середня оцінка курсу рахується лише по тих, хто її поставив. Якщо треба вважати
відсутнє значення нулем — `AVG(COALESCE(rating, 0))`.

## Правило GROUP BY

Кожен стовпець у `SELECT` має бути або в `GROUP BY`, або всередині агрегатної функції.
Запит `SELECT city, email, COUNT(*) FROM users GROUP BY city` не має сенсу: у групі «Київ» сотня email —
який із них показати?

## WHERE чи HAVING

`WHERE` фільтрує **рядки до** групування, `HAVING` фільтрує вже згруповані рядки:

```sql
SELECT date_trunc('week', created_at) AS week, SUM(total) AS revenue
FROM orders
WHERE status = 'paid'
GROUP BY 1
HAVING SUM(total) > 100000;
```

Тут `WHERE` прибирає неоплачені замовлення, а `HAVING` залишає лише тижні з виручкою понад 100 000.
Умови, що не стосуються агрегатів, завжди ставте у `WHERE` — так база обробить менше рядків.

## Умовна агрегація

Кілька метрик з різними умовами можна порахувати одним проходом:

```sql
SELECT date_trunc('month', created_at) AS month,
       COUNT(*) FILTER (WHERE status = 'paid')     AS paid,
       COUNT(*) FILTER (WHERE status = 'refunded') AS refunded,
       ROUND(100.0 * COUNT(*) FILTER (WHERE status = 'refunded') / COUNT(*), 1) AS refund_rate
FROM orders
GROUP BY 1;
```

`FILTER` — синтаксис PostgreSQL. У базах без нього те саме робить `SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END)`.

Зверніть увагу на `100.0`: ділення двох цілих чисел у PostgreSQL дає ціле число, і частка 3/40 перетвориться на 0.

## Пропущені періоди

Якщо в якийсь тиждень не було замовлень, `GROUP BY` просто не поверне для нього рядка, і на графіку
з'явиться оманлива пряма лінія. Згенеруйте повний ряд дат і приєднайте до нього дані:

```sql
SELECT w.week, COALESCE(SUM(o.total), 0) AS revenue
FROM generate_series('2026-08-03'::date, '2026-11-02', interval '1 week') AS w(week)
LEFT JOIN orders o ON date_trunc('week', o.created_at) = w.week
GROUP BY w.week
ORDER BY w.week;
```
