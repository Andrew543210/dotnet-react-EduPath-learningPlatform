## Агрегат без схлопування рядків

`GROUP BY` перетворює групу рядків на один рядок: сто замовлень користувача стають одним рядком
із сумою. Але часто потрібно інше — зберегти кожне замовлення і поруч показати агрегат: номер замовлення
у клієнта, накопичену суму, відхилення від середнього. Віконна функція рахує агрегат по групі рядків,
але не схлопує рядки — це її головна відмінність від `GROUP BY`.

```sql
SELECT user_id, created_at, total,
       ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at) AS nth,
       SUM(total)   OVER (PARTITION BY user_id ORDER BY created_at) AS running_total
FROM orders;
```

```text
user_id | created_at | total | nth | running_total
--------+------------+-------+-----+--------------
7       | 2026-08-02 | 450   | 1   | 450
7       | 2026-09-14 | 690   | 2   | 1140
7       | 2026-10-21 | 300   | 3   | 1440
12      | 2026-08-19 | 790   | 1   | 790
```

## Анатомія OVER

- **PARTITION BY** ділить рядки на групи. `PARTITION BY user_id` рахує вікно окремо для кожного
  користувача: нумерація і сума починаються заново для кожного `user_id`. Без `PARTITION BY`
  вікно — уся таблиця.
- **ORDER BY** всередині вікна задає порядок для накопичувальних сум і нумерації.
- **Рамка** (`ROWS BETWEEN ...`) уточнює, які рядки входять у вікно для поточного рядка.

## Функції нумерації

| Функція | Значення для сум 900, 700, 700, 500 |
|---|---|
| `ROW_NUMBER()` | 1, 2, 3, 4 — завжди унікальний номер |
| `RANK()` | 1, 2, 2, 4 — однакові значення ділять місце, далі пропуск |
| `DENSE_RANK()` | 1, 2, 2, 3 — без пропусків |

`ROW_NUMBER()` пронумерує замовлення кожного користувача, і з нього легко взяти перше замовлення:

```sql
WITH numbered AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at) AS nth
  FROM orders
)
SELECT * FROM numbered WHERE nth = 1;
```

Фільтрувати за віконною функцією в `WHERE` того самого запиту не можна — вона обчислюється на етапі `SELECT`.
Тому потрібен CTE або підзапит.

## Зсуви: LAG і LEAD

`LAG` бере значення з попереднього рядка вікна, `LEAD` — з наступного. Скільки днів минуло між покупками:

```sql
SELECT user_id, created_at,
       created_at - LAG(created_at) OVER (PARTITION BY user_id ORDER BY created_at) AS since_previous
FROM orders;
```

Тиждень до тижня:

```sql
WITH weekly AS (
  SELECT date_trunc('week', created_at) AS week, SUM(total) AS revenue
  FROM orders GROUP BY 1
)
SELECT week, revenue,
       ROUND(100.0 * (revenue / LAG(revenue) OVER (ORDER BY week) - 1), 1) AS growth_pct
FROM weekly;
```

## Рамка вікна: ковзне середнє

```sql
SELECT week, revenue,
       AVG(revenue) OVER (ORDER BY week ROWS BETWEEN 3 PRECEDING AND CURRENT ROW) AS avg_4_weeks
FROM weekly;
```

Ковзне середнє за чотири тижні згладжує шум на графіку. Якщо вказати `ORDER BY` без рамки,
PostgreSQL використовує `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — накопичувальну суму від початку.

## Частка від загального

```sql
SELECT city, SUM(total) AS revenue,
       ROUND(100.0 * SUM(total) / SUM(SUM(total)) OVER (), 1) AS share_pct
FROM orders o JOIN users u ON u.id = o.user_id
GROUP BY city;
```

Віконна функція над агрегатом: `SUM(SUM(total)) OVER ()` — загальна сума по всіх групах.

## Практика

Для кожного користувача знайдіть суму першого замовлення, середній інтервал між покупками і різницю
між останнім і першим чеком. Окремо побудуйте тижневу виручку з ковзним середнім за чотири тижні.
