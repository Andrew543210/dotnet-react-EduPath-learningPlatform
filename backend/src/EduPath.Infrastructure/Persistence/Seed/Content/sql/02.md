## Види з'єднань

`JOIN` поєднує рядки двох таблиць за умовою. Від виду з'єднання залежить, що станеться з рядками без пари.

| З'єднання | Що повертає |
|---|---|
| `INNER JOIN` | лише рядки, що мають пару в обох таблицях |
| `LEFT JOIN` | усі рядки лівої таблиці; якщо пари немає — `NULL` у полях правої |
| `RIGHT JOIN` | дзеркально до `LEFT`, на практиці майже не використовується |
| `FULL JOIN` | усі рядки обох таблиць |

Щоб отримати користувачів разом із тими, хто ще нічого не купив, потрібен `LEFT JOIN users → orders`:

```sql
SELECT u.id, u.email, COUNT(o.id) AS orders
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.email;
```

Зверніть увагу на `COUNT(o.id)`, а не `COUNT(*)`: для користувача без замовлень `COUNT(*)` поверне 1
(рядок із `NULL`), а `COUNT(o.id)` — 0.

**Пастка LEFT JOIN.** Умова на праву таблицю у `WHERE` перетворює його на `INNER`:

```sql
-- користувачі без замовлень зникнуть: у них o.status = NULL
LEFT JOIN orders o ON o.user_id = u.id
WHERE o.status = 'paid'

-- правильно: умова в ON
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'paid'
```

## Звідки береться «зайва» виручка

Аналітик рахує виручку і кількість проданих товарів одним запитом:

```sql
SELECT SUM(o.total) AS revenue, SUM(i.quantity) AS items
FROM orders o
JOIN order_items i ON i.order_id = o.id;
```

Виручка виходить утричі більшою, ніж у фінансового відділу. Причина: після з'єднання кожне замовлення
повторюється для кожної позиції. Замовлення на 1 000 грн із трьома позиціями дає три рядки,
і `SUM(o.total)` врахує його тричі — 3 000 грн.

```text
order_id | total | product
---------+-------+---------
1        | 1000  | Книга
1        | 1000  | Блокнот
1        | 1000  | Ручка
```

## Як рахувати правильно

Рахуйте агрегати **на рівні тієї таблиці, якій вони належать**, а потім з'єднуйте результати:

```sql
WITH items AS (
  SELECT order_id, SUM(quantity) AS items
  FROM order_items
  GROUP BY order_id
)
SELECT SUM(o.total) AS revenue, SUM(i.items) AS items
FROM orders o
LEFT JOIN items i ON i.order_id = o.id;
```

Тепер кожне замовлення — один рядок, і `SUM(o.total)` рахує його один раз.

`SUM(DISTINCT o.total)` — поширена, але неправильна «латка»: два різні замовлення на однакову суму
злипнуться в одне.

## Як помітити проблему

Перед агрегацією перевірте, скільки рядків дає з'єднання:

```sql
SELECT COUNT(*), COUNT(DISTINCT o.id)
FROM orders o
JOIN order_items i ON i.order_id = o.id;
```

Якщо числа відрізняються, рядки «розмножилися», і суми полів з `orders` будуть завищені. Корисна звичка —
формулювати для себе **зернистість** результату: «один рядок = одне замовлення» чи «один рядок = одна позиція».

## Практика

Порахуйте для кожного міста кількість користувачів, кількість замовлень і виручку одним запитом.
Переконайтеся, що міста без замовлень теж потрапили в результат, а виручка збігається з `SUM(total)` по таблиці `orders`.
