## Скільки людей повертаються через місяць

Загальна кількість активних покупців росте — це добре? Не обов'язково. Можливо, маркетинг заливає
трафік, а люди купують один раз і зникають. Когортний аналіз відповідає на точніше питання: яка частка
людей, що вперше купили в певному місяці, повертається через один, два, три місяці.

**Когорта** — група користувачів з однаковою подією старту. У цьому аналізі когорту користувача визначає
місяць першої покупки.

## Алгоритм

1. Для кожного користувача знайдіть місяць першої покупки — це когорта.
2. Для кожного замовлення порахуйте номер місяця від когорти: 0 — місяць першої покупки, 1 — наступний тощо.
3. Порахуйте унікальних покупців у кожній клітинці «когорта × місяць».
4. Поділіть на розмір когорти, щоб отримати відсоток утримання.

## Запит

```sql
WITH paid AS (
  SELECT user_id, created_at FROM orders WHERE status = 'paid'
),
cohorts AS (
  SELECT user_id, date_trunc('month', MIN(created_at)) AS cohort
  FROM paid
  GROUP BY user_id
),
activity AS (
  SELECT c.cohort,
         p.user_id,
         (EXTRACT(YEAR FROM age(date_trunc('month', p.created_at), c.cohort)) * 12
          + EXTRACT(MONTH FROM age(date_trunc('month', p.created_at), c.cohort)))::int AS month_number
  FROM paid p
  JOIN cohorts c USING (user_id)
),
counts AS (
  SELECT cohort, month_number, COUNT(DISTINCT user_id) AS buyers
  FROM activity
  GROUP BY cohort, month_number
)
SELECT cohort,
       month_number,
       buyers,
       ROUND(100.0 * buyers / FIRST_VALUE(buyers) OVER (PARTITION BY cohort ORDER BY month_number), 1) AS retention_pct
FROM counts
ORDER BY cohort, month_number;
```

У клітинці таблиці утримання рахують саме **унікальних** покупців (`COUNT(DISTINCT user_id)`), а не замовлення:
людина з п'ятьма покупками за місяць — це один утриманий користувач. Віконна функція `FIRST_VALUE`
бере перше значення у вікні когорти — її розмір у нульовому місяці.

## Як читати таблицю

Результат розгортають у трикутну таблицю: рядки — когорти, стовпці — місяці від старту.

| Когорта | Розмір | М1 | М2 | М3 |
|---|---|---|---|---|
| 2026-07 | 120 | 28 % | 19 % | 16 % |
| 2026-08 | 145 | 31 % | 22 % | 18 % |
| 2026-09 | 160 | 36 % | 25 % | |
| 2026-10 | 170 | 38 % | | |

- **Рядок** показує, як «згасає» одна когорта. Якщо крива виходить на плато (16–18 %), у продукту є
  ядро постійних клієнтів.
- **Стовпець** порівнює когорти між собою на однаковому етапі життя. Тут утримання першого місяця
  росте з 28 % до 38 % — щось у продукті покращилося.
- **Діагональ** — один календарний місяць для всіх когорт. Просідання по діагоналі вказує на зовнішню подію:
  сезонність, збій оплати, конкурента.

Таблиця утримання показує, чи покращуються нові когорти після змін у продукті, — те, чого не видно
в загальній кількості активних користувачів.

## Типові помилки

- **Неповний останній місяць.** Когорта жовтня ще не мала шансу повернутися в листопаді, якщо листопад не закінчився.
  Обрізайте незавершені періоди.
- **Маленькі когорти.** 30 % від 10 людей — це три людини. Показуйте розмір когорти поруч із відсотками.
- **Змішування подій.** Когорта за реєстрацією і когорта за першою покупкою відповідають на різні питання.

## Практика

Побудуйте когортну таблицю утримання для навчальної бази й розгорніть її в трикутну форму в таблиці або BI-інструменті.
Визначте, на якому місяці крива виходить на плато і чи покращувалися когорти протягом року.
